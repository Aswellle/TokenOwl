# TokenOwl 安全、隐私、测试与发布规范

## 1. 隐私原则

TokenOwl 的默认定位：**local-first**。

默认：

- 不创建 TokenOwl 云端账户；
- 不上传 Provider credentials；
- 不上传 quota data；
- 不上传浏览历史；
- 不启用遥测；
- 不把 provider response 写入远程日志。

---

## 2. Secret 存储

仅使用 OS credential store：

- Windows Credential Manager
- macOS Keychain

Rust `keyring` 可用于跨平台封装。参考：
https://docs.rs/keyring/latest/keyring/v1/

数据库只保存：

```text
credential_ref = keyring://tokenowl/provider/<account-id>
```

---

## 3. Secret Redaction

所有日志必须经过：

```text
Authorization
X-API-Key
Cookie
Set-Cookie
Bearer
access_token
refresh_token
client_secret
password
```

脱敏：

```text
Authorization: Bearer sk-******abcd
Cookie: session=***redacted***
```

CI 日志中禁止出现完整 secret。

---

## 4. Browser Session / Cookie

浏览器 cookie 属于高敏感凭据。

默认关闭自动抓取。

如果后续实现：

1. 明确显示来源；
2. 用户主动点击授权；
3. 最小权限；
4. 优先读取特定域名；
5. 不把 cookie 导出到网络；
6. 可以随时清除；
7. provider terms 允许的范围内使用；
8. UI 明确说明这是高级连接方式。

---

## 5. Custom Endpoint 安全

因为 TokenOwl 允许用户连接私有 endpoint，必须防止 Manifest 误用：

### 允许

- HTTPS 公网地址；
- 用户明确添加的 HTTP/LAN 地址。

### 默认阻止

- file://
- `chrome://`
- `data:`
- 本地任意文件读取；
- manifest 隐式访问 localhost。

用户手动允许 LAN 时再放开：

```text
localhost
127.0.0.1
192.168.*
10.*
172.16–31.*
```

---

## 6. SSRF / URL 安全

Provider manifest 禁止任意重定向到未知域名。

建议：

- manifest endpoints 显式声明；
- redirect 默认 off；
- 如果用户开启 redirect，则每次 redirect 检查 host；
- 禁止携带 Authorization header 到跨 host redirect。

---

## 7. Provider TOS

TokenOwl 应优先使用：

- 官方公开 API；
- 官方 OAuth；
- Provider 明确授权的 usage/billing API。

Web dashboard / browser session adapter 属于高级兼容路径，必须明确标注“可能受 Provider API/TOS 变化影响”。

## 16. Release

版本遵循 SemVer。

```text
MAJOR
MINOR
PATCH
```

Tag：

```text
v0.1.0
```

Release 必须保存：

- installer；
- checksums；
- changelog；
- version metadata。

不要自动删除旧 Release assets。

---

## 17. Update

Updater 必须：

- signature verification；
- atomic replacement；
- rollback strategy；
- update failure 不破坏旧版本；
- 不影响本地 SQLite / keychain。

---

## 18. Backup / Migration

Schema migration：

```text
001_initial
002_quota_window
003_provider_manifest
004_usage_history
...
```

每次 migration 前检查 DB integrity。

升级失败必须：

1. 保留旧 DB；
2. 生成 backup；
3. 回滚或恢复到 safe mode。
