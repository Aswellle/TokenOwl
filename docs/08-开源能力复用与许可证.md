# TokenOwl 开源能力复用与许可证策略

## 1. 总原则

TokenOwl 不重复造“已经成熟的 Provider 知识”，但也不把整个第三方项目塞进桌面应用。

策略：

```text
复用协议思想
复用数据结构经验
复用明确许可的可移植代码
复用公开模型/价格 catalog
自研 TokenOwl Domain + UI + Scheduler
```

许可证最终以实际采用 commit / 文件头 / LICENSE 为准，并在发布前由人工进行一次合规复核。

## 2. CodexBar

Repository：
https://github.com/steipete/CodexBar

当前项目 README / provider 列表已经覆盖多种额度 source，包括：

- OpenAI / Codex
- Anthropic / Claude
- Cursor
- Alibaba Coding Plan
- Alibaba Token Plan
- Qwen Cloud
- Kimi
- MiniMax
- Moonshot/Kimi API
- Doubao
- DeepSeek
- z.ai
- Xiaomi MiMo
- 以及其他 Provider。

它特别值得 TokenOwl 研究的，是 Provider descriptor、不同 data source、reset countdown、多 Provider 聚合的产品化方式。

许可证：MIT（当前仓库页面明确显示 MIT）。

建议：

```text
✅ 阅读 / 研究
✅ 根据 MIT 条款复制明确需要的代码
✅ 重写为 Rust Provider Adapter
✅ 参考其 Provider capability matrix

❌ 不整体嵌入 Swift/macOS UI
❌ 不直接把 CodexBar 当 TokenOwl backend
```

## 3. ccusage

Repository：
https://github.com/ccusage/ccusage

当前项目支持多个 coding-agent 本地 usage source，并提供 5-hour blocks、daily、weekly、monthly、JSON 等能力。

建议用途：

```text
Local Usage Source
Local JSONL parser 思路
5h usage block 领域逻辑参考
```

TokenOwl 不应强制用户安装 Node/Bun；优先复用数据协议/解析思路，必要时移植核心逻辑到 Rust。

许可证在采用前再次核对仓库 LICENSE。

---

## 4. LiteLLM

Repository：
https://github.com/BerriAI/litellm

当前 README 描述其统一支持 100+ LLM providers，并提供 cost tracking 等能力。

TokenOwl 最值得复用：

- Provider catalog 思路；
- OpenAI-compatible；
- model/provider mapping；
- pricing metadata；
- custom provider。

不建议：

```text
直接嵌入整个 Python gateway
```

原因：TokenOwl 是 desktop monitor，不需要在用户机器上运行一套完整 AI gateway。

许可证：核心仓库页面显示 MIT，但具体引用内容仍需按目录、版本和许可证逐文件确认；不要默认所有附属目录/组件拥有同一许可证。

## 6. New API

Repository：
https://github.com/QuantumNous/new-api

它适合：

- Provider/channel model 参考；
- OpenAI/Claude/Gemini compatible gateway 兼容测试；
- quota/billing 领域参考；
- 未来 TokenOwl 连接用户自建 New API 实例。

当前仓库页面显示 AGPL-3.0。

因此 TokenOwl：

```text
✅ 连接 New API 实例
✅ 学习架构
✅ 参考 API 行为
❌ 未经合规审查直接拷贝核心代码
❌ 将 AGPL 代码混入闭源核心而不做许可评估
```

## 7. models.dev

Repository：
https://github.com/anomalyco/models.dev

当前仓库提供开放模型数据库，并区分 provider-specific serving details 与 provider-agnostic model metadata，同时提供 API 与 provider logos。

TokenOwl 可作为：

```text
Build-time model catalog source
Price metadata source
Capability metadata source
Provider logo source
```

不要让 TokenOwl 的核心 quota 数据依赖 models.dev；模型目录与账户额度是两个不同问题。

当前仓库页面显示 MIT。

## 9. 第三方代码进入 TokenOwl 前必须检查

```text
Repository LICENSE
Source file header
SPDX identifier
Dependency license
Transitive dependency license
Generated code license
Logo/trademark restrictions
Attribution requirements
Notice requirements
```

建议建立：

```text
THIRD_PARTY_NOTICES.md
```

内容包含：

```text
Component
Version/Commit
License
Source URL
Files reused
Modification summary
Attribution requirement
```

## 10. 禁止的“复制粘贴开发”

Agent 不能：

- 搜到 Provider adapter 后直接整目录复制；
- 混入其他项目 build system；
- 引入 Python/Node runtime 只为了运行一个 parser；
- 不记录源仓库 commit；
- 不处理许可证；
- 直接修改第三方代码后当成自己的维护代码。

正确方式：

```text
研究
 ↓
选择最小能力
 ↓
确认许可证
 ↓
建立 TokenOwl-native abstraction
 ↓
迁移必要逻辑
 ↓
增加 fixture / tests
 ↓
记录来源
```
